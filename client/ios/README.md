# Oshinobu — iOS

Нативный iOS-клиент: Swift, SwiftUI, CryptoKit, URLSession — без сторонних библиотек в ядре.
Протокол и формат на проводе — те же, что у Android (`client/android/client-kotlin`):
X3DH + Double Ratchet, REST + WebSocket. iOS и Android переписываются друг с другом.

Код начат 2026-10-26 и написан **вслепую** (на Linux-ПК нет Xcode и Swift). 2026-11-04 впервые
собран на Mac (Xcode 27.2, Swift 6.4): приложение собирается без ошибок и предупреждений,
`swift test` ядра зелёный — векторы протокола Android проходят. В симуляторе и на устройстве
ещё не запускался.

    Storage/           Keychain/UserDefaults, KeyStore, SessionStore (с архивом сессий),
                       ChatStore (история — файлы под Data Protection), StoredMessage
    Service/           KeyedMutex, AckRegistry, SendQueueProcessor, PeerMessenger,
                       DeviceSetup, MessageRouter (самолечение, архив сессий, все типы)
    Support/           JSONValue (точные целые для AAD), Broadcast/StateValue
    OshinobuCore.swift фасад: вход, сессия, отправка текста, чтение
  Tests/OshinobuCoreTests/
    ProtocolVectorsTests  та же стенограмма, что у Android (protocol_transcript.json):
                          если зелёный — iOS понимает Android и наоборот

  project.yml          проект для XcodeGen (сам .xcodeproj не храним)

## Сборка (на Mac)

```
brew install xcodegen
cd client/ios/Oshinobu && xcodegen        # → Oshinobu.xcodeproj
cd ../OshinobuCore && swift test          # ядро и векторы протокола (macOS 14+)
open ../Oshinobu/Oshinobu.xcodeproj       # iOS 18+, подпись — свой Team
```

Сборка из консоли без подписи (проверка компиляции):

```
cd client/ios/Oshinobu && xcodebuild -project Oshinobu.xcodeproj -scheme Oshinobu \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```

На iPhone — подписью команды из `project.yml` (`JD9PBY7P74`), с пушами:

```
xcodebuild -project Oshinobu.xcodeproj -scheme Oshinobu -destination 'generic/platform=iOS' \
  -allowProvisioningUpdates build
```

Жесты на устройстве — UI-тесты `UITests/GestureTests.swift` (XCUITest нажимает как палец: удержание
записи, фиксация замочком, кружок с отменой влево, скрепка при поднятой клавиатуре):

```
xcodebuild -project Oshinobu.xcodeproj -scheme Oshinobu -destination id=<UDID> -allowProvisioningUpdates \
  -only-testing:OshinobuUITests/GestureTests/testHoldRecord test
```

`testHoldRecord` отправляет короткое голосовое в первый чат списка, остальные тесты запись отменяют.

Сгенерированные `Oshinobu.xcodeproj`, `Info.plist` и `Oshinobu.entitlements` в git не кладём
(`client/ios/.gitignore`).

## Решения

- **Минимум iOS 18** (с 2026-11-04; было 17) — жесты строки сообщения на UIKit через
  `UIGestureRecognizerRepresentable` (тап, двойной тап, удержание с протяжкой, свайп-ответ одним
  автоматом, как `MessageRow` на Android); ядро `OshinobuCore` по-прежнему собирается от iOS 17.
- **Хранение.** Ключи, сессии ratchet, очереди — Keychain, `AfterFirstUnlockThisDeviceOnly`:
  не уезжают в iCloud и резервные копии (после переустановки — новое устройство, как на Android),
  доступны при заблокированном экране (входящий пуш/звонок). История чатов — файлы в Application
  Support под `completeUntilFirstUserAuthentication` + кэш в памяти (Keychain не для больших данных).
- **Архив сессий** и запрет каскада автосбросов — как на Android с `+70`.
- Формат хранения на iOS свой (наследия Flutter нет), имена ключей те же, что у Android.

  скрыт). Токены — `POST /push/register-apns`, sandbox для сборок из Xcode (`DEBUG`).
